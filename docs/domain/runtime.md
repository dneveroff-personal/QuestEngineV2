# Runtime Model

## Назначение

Runtime Model описывает состояние Quest во время фактического проведения игры.

Основной принцип:

> Статические сущности описывают правила игры, Runtime-сущности описывают фактическое прохождение игры командами.

---

# Static Model

Автор заранее создаёт:

```text
Quest
 └── Level
      ├── Code
      └── Hint
```

Эти сущности описывают сценарий игры.

---

# Runtime Model

Во время игры появляются:

```text
QuestProgress
 └── LevelProgress
       ├── CodeSubmission
       └── HintProgress
```

Каждая команда имеет собственный `QuestProgress`.

---

# QuestProgress

`QuestProgress` представляет прохождение одного Quest одной конкретной командой.

Связь:

```text
Quest 1 ──── N QuestProgress
Team 1  ──── N QuestProgress
```

Один Quest может иметь множество QuestProgress.

Одна Team может иметь множество QuestProgress, в том числе одновременно.

---

# Создание QuestProgress

Для подтверждённой команды `QuestProgress` создаётся в момент старта Quest.
Если автор подтверждает команду после начала Quest, её QuestProgress создаётся в момент подтверждения.
Команда при этом начинает прохождение с текущего состояния игры.

---

# QuestProgress lifecycle

```text
WAITING
   ↓
RUNNING
   ├── FINISHED
   └── DNF
```

## WAITING

Прохождение создано, но команда ещё не начала взаимодействовать с игрой.
Это состояние может использоваться для подтверждённой команды до её первого входа.
Игровое время при этом уже может идти.

---

## RUNNING

Команда находится в процессе прохождения Quest.
У неё есть активный `LevelProgress`.

---

## FINISHED

Команда прошла последний уровень.
Итоговое время зафиксировано.

---

## DNF

Quest завершён автором или по правилам игры, но команда не прошла все уровни.

DNF означает:

```text
Did Not Finish
```

DNF является итоговым результатом конкретного QuestProgress.

---

# LevelProgress

Для каждого Level создаётся отдельный `LevelProgress` для каждой команды.

Например:

```text
Quest
 ├── Level 1
 ├── Level 2
 └── Level 3

Team A
 ├── LevelProgress 1
 ├── LevelProgress 2
 └── LevelProgress 3
```

LevelProgress сохраняется как история прохождения.

Одновременно активным может быть только один LevelProgress.

---

# Первый LevelProgress

Первый `LevelProgress` создаётся в момент первого входа команды в Quest.
При этом время автоперехода первого уровня рассчитывается от общего времени старта Quest, а не от времени входа команды.

Например:
Quest start = 21:00

Level 1:
auto-transition = 60 минут

Команда вошла в 21:30.

Тогда:
openedAt = 21:30
autoTransitionAt = 22:00

Команда получила только оставшиеся 30 минут.
Если команда вошла после 22:00, например в 22:30, первый уровень сразу считается пройденным по автопереходу.
Поздний вход не предоставляет команде дополнительного времени.

---

# Последующие LevelProgress
Каждый следующий `LevelProgress` создаётся только после завершения предыдущего.
Для второго и последующих уровней `autoTransitionAt` рассчитывается от фактического `openedAt` этого уровня:

`autoTransitionAt = openedAt + timeout`
Таким образом, после прохождения предыдущего уровня команда получает полный отведённый автором интервал для следующего уровня.

---

# Завершение LevelProgress

LevelProgress может завершиться двумя основными способами:

```text
CODES
AUTO_TRANSITION
```

### CODES

Команда ввела необходимое количество правильных кодов.

### AUTO_TRANSITION

Время уровня истекло.

---

# Уровни без кодов

Level может не иметь кодов.

Если для такого уровня задан автопереход, уровень завершается только по времени.

Такие уровни могут использоваться как сюжетные вставки или "заглушки".

---

# CodeSubmission

Каждая отправка кода является отдельным runtime-событием.

Система фиксирует:

* команду;
* QuestProgress;
* LevelProgress;
* введённое значение;
* время отправки;
* результат проверки.

Результат может быть:

```text
ACCEPTED
REJECTED
```

---

# HintProgress

HintProgress фиксирует открытие конкретной подсказки для конкретной команды.

Подсказки не открываются одновременно для всех команд.

Время открытия рассчитывается относительно начала соответствующего LevelProgress.

---

# Bonus and Penalty Time

Runtime должен хранить начисленные бонусы и штрафы.

Итоговое время:

```text
FinalTime =
    GameTime
    - BonusTime
    + PenaltyTime
```

Бонус уменьшает итоговое время.

Штраф увеличивает итоговое время.

---

# Runtime Isolation

QuestProgress одной команды не изменяет QuestProgress другой команды.

Например:

```text
Team A
QuestProgress A
 └── LevelProgress A1

Team B
QuestProgress B
 └── LevelProgress B1
```

Команды используют один и тот же Quest и Level,

но их runtime-состояния полностью независимы.

---

# Statistics

Statistics строится на основе Runtime Model.

Основными источниками являются:

* QuestProgress;
* LevelProgress;
* CodeSubmission;
* Bonus Time;
* Penalty Time.

Во время игры статистика является текущим состоянием соревнования.

После завершения Quest она становится итоговым результатом.
