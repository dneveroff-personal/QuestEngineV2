# Level

## Назначение
Level представляет собой одно игровое задание Quest. Quest состоит из последовательности Level. Каждый Level описывается автором Quest и является частью шаблона игры. Во время прохождения игры каждая команда получает собственный экземпляр прохождения уровня — `LevelProgress`.

---

# Структура
Каждый Level содержит:
- название;
- описание задания;
- порядковый номер;
- список кодов;
- список подсказок;
- настройки прохождения.

---

# Порядок
Level всегда принадлежит одному Quest. Порядок прохождения определяется номером уровня. После начала Quest структура и порядок уровней не изменяются.

---

# Коды
Level может содержать любое количество игровых кодов. Каждый код может иметь несколько **синонимов** — допустимых вариантов написания правильного ответа. Ввод любого синонима засчитывает весь код.

Автор самостоятельно определяет:
- количество кодов и синонимов внутри каждого;
- текст каждого синонима;
- регистр символов;
- необходимость уникальности (в пределах уровня, см. ADR-0004).

---

# Количество необходимых кодов
Автор может указать, сколько кодов необходимо решить для завершения уровня — это не обязательно все коды уровня.

Если порог не задан явно — по умолчанию требуются **все** коды уровня.

Во время игры команда видит подсказку прогресса «Осталось ввести {N} из {M} кодов» (см. `code-submission.md`).

Подробная модель (коды, синонимы, порог, таксономия из 5 типов уровня) — ADR-0005, детали ввода — `code-submission.md`.

---

# Уровень без кодов
Level может вообще не содержать игровых кодов. Такие уровни используются для сюжетных вставок, переездов, ожидания старта следующего этапа. Прохождение подобных уровней возможно только по автопереходу — обязательному в этом случае.

---

# Автопереход
Автор может задать время автоматического завершения уровня. Если команда не выполнила условия прохождения, после истечения времени уровень завершается автоматически.

Причина завершения: `AUTO_TRANSITION`.

---

# Первый уровень
Первый уровень обладает особым поведением. Таймер первого уровня начинает отсчёт в момент старта Quest. Если команда вошла позже, она получает только оставшееся время. Если время автоперехода уже закончилось, уровень завершается сразу после входа команды в игру.

---

# Последующие уровни
Для всех остальных уровней таймер начинает отсчёт в момент открытия уровня конкретной команде. Автопереход каждого следующего уровня рассчитывается относительно времени его открытия.

---

# Подсказки
Level может содержать несколько подсказок.

Для `REGULAR`-подсказок показ выполняется автоматически через заданное автором время.
`BONUS`/`PENALTY`-подсказки доступны команде для явного взятия после наступления времени доступности; до взятия команда видит тип, но не содержимое и точное значение эффекта.

Каждая подсказка имеет собственное время доступности. Подробная runtime-механика описана в `hint-progress.md`, ADR-0020 и ADR-0021.

---

# Типы подсказок

## Regular
Обычная подсказка. Показывается автоматически по таймеру и не влияет на итоговое время команды.

## Bonus
После явного взятия командой начисляет бонусное время.

## Penalty
После явного взятия командой начисляет штрафное время.

Конкретная логика начисления бонусов и штрафов определяется правилами `01-domain/bonus-penalty.md`.

---

## LevelProgress

Во время прохождения Quest каждый Level порождает собственный `LevelProgress`.

`LevelProgress` хранит runtime-состояние прохождения уровня:
- время открытия;
- время завершения;
- время автоперехода;
- статус прохождения.

`LevelProgress` связан с событиями ввода кодов, использованием подсказок, бонусами и штрафами через соответствующие runtime-сущности.

---

# Инварианты
- Level принадлежит только одному Quest.
- Последовательность уровней неизменяема.
- Один Level может иметь множество Code.
- Один Level может иметь множество Hint.
- Один Level порождает один LevelProgress для каждой команды.
- Одновременно активным может быть только один LevelProgress.
- Следующий уровень открывается только после завершения предыдущего.
