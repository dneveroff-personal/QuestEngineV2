# Hint Progress

Статус: 🟢 Accepted, Implemented. Модель зафиксирована ADR-0020 (типы, auto-reveal для REGULAR) и ADR-0021 (явное взятие для BONUS/PENALTY).

## Назначение

`Hint` — подсказка, привязанная к `Level`, созданная автором на этапе редактирования (CRUD в `hint/service`).
`HintProgress` — факт того, что подсказка была показана/взята конкретной командой во время игры.

---

## Модель подсказки (реализовано)

`Hint`:
- `level` — к какому уровню относится;
- `orderIndex` — порядок среди подсказок уровня;
- `delaySeconds` — через сколько секунд после открытия уровня подсказка становится доступной;
- `content`;
- `type` (enum `REGULAR` / `BONUS` / `PENALTY`, аналог `CodeType`);
- `bonusPenaltySeconds` (Integer, nullable, обязателен для `BONUS`/`PENALTY`, консистентно с `Code.bonusPenaltySeconds` — ADR-0006).

---

## Два разных механизма показа, в зависимости от типа (ADR-0020 + ADR-0021)

`hintAvailableAt = LevelProgress.openedAt + Hint.delaySeconds`

### REGULAR — auto-reveal (без действия команды)

Показывается **автоматически** по достижении `hintAvailableAt` — планировщиком (Job 3, `HintRevealScheduler`), без участия команды. Ручное «открытие» не предусмотрено и не нужно — подсказка бесплатна, отказываться не от чего.

### BONUS / PENALTY — явное взятие (ADR-0021)

По достижении `hintAvailableAt` подсказка становится **доступной для взятия**, но **не показывается автоматически**. Job 3 её не трогает. Команда должна явно вызвать действие «взять» (`POST .../hints/{hintId}/take`), чтобы увидеть содержимое и получить/понести эффект.

**Что видно команде до взятия**: факт доступности (`hintId`, `orderIndex`) и **тип** (`BONUS` или `PENALTY` — команда знает знак эффекта). **Не видно**: точное значение `bonusPenaltySeconds` и `content` — решение принимается вслепую относительно конкретной цены и содержания.

**Окно решения**: взять можно **в любой момент**, пока `LevelProgress` в статусе `ACTIVE` — не обязательно сразу, как только появилась возможность.

**Кто может взять**: любой участник команды (тот же принцип, что и ввод кодов — не только капитан).

---

## Типы подсказки и эффект

| Тип | Механизм | Эффект |
|---|---|---|
| `REGULAR` | Auto-reveal (Job 3) | Не влияет на итоговое время. |
| `BONUS` | Явное взятие командой | При взятии начисляет `bonusPenaltySeconds` как бонусное время (см. `bonus-penalty.md`). Ожидается, что этот тип будет использоваться редко на практике. |
| `PENALTY` | Явное взятие командой | При взятии начисляет `bonusPenaltySeconds` как штрафное время (см. `bonus-penalty.md`). Основной практический случай — например, штрафные подсказки для команд, застрявших на уровне. |

## HintProgress как runtime-сущность (реализовано)

Поля:
- `id`
- `levelProgress` (ManyToOne)
- `hint` (ManyToOne)
- `shownAt` — момент показа (для REGULAR — момент auto-reveal; для BONUS/PENALTY — момент явного взятия командой)

`openedBy`/`takenBy` не хранится — как и раньше, действие командное, а не персональное (для аудита, кто именно из участников нажал «взять», отдельного требования не поступало; при необходимости можно добавить позже).

Инварианты:
- Одна и та же `Hint` не может быть показана/взята дважды для одного `LevelProgress` — идемпотентно (повторный вызов "взять" для уже взятой подсказки не создаёт дубликата и не повторяет эффект).
- `HintProgress` не создаётся раньше `hintAvailableAt` — ни через auto-reveal, ни через попытку взять досрочно (сервер сам решает, наступило ли время, не доверяя клиенту — `05-security/threat-model.md`).
- `HintProgress` привязан к конкретному `LevelProgress` — при переходе на новый уровень отсчёт начинается заново.
- Взять можно только для активного (`ACTIVE`) `LevelProgress` — попытка взять подсказку неактивного уровня отклоняется.

## GET-эндпоинт: что видит команда

`GET /api/quests/progress/{questId}/{teamId}/hints` возвращает список видимых команде подсказок текущего активного уровня, в одном из трёх состояний на подсказку:

1. **Не наступило время** (`now < hintAvailableAt`) — подсказка вообще не включается в ответ (не палим существование будущих подсказок).
2. **REGULAR, показана** или **BONUS/PENALTY, взята** — полный набор полей, включая `content` и точный `bonusPenaltySeconds`.
3. **BONUS/PENALTY, доступна, но не взята** — только `hintId`, `orderIndex`, `type`; `content` и `bonusPenaltySeconds` — `null`.

---

## Ручное досрочное открытие автором (решено — не в MVP)

Автор не может вручную показать подсказку раньше `hintAvailableAt` в MVP.

## Будущее улучшение: персональные подсказки для конкретных команд

Отложено за пределы MVP: автор сможет создавать подсказку, видимую только выбранной команде (или нескольким), не всем участникам квеста. Отдельная модель данных, не специфицирована подробно.

---

## Видимость подсказок другим командам

Подсказки, показанные/взятые одной командой, не видны другим командам — как и решение "доступна, не взята" (иначе можно узнавать структуру уровня, наблюдая за соперниками).

## Связь со Статистикой (решено)

Автору доступна полная статистика — какая команда сколько `BONUS`/`PENALTY`-подсказок взяла на каждом уровне; командам — только своя.
