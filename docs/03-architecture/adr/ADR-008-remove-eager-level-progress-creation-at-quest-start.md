# ADR-0008 — Remove Eager LevelProgress Creation At Quest Start (Amends ADR-0002)

## Status

Accepted — амендирует ADR-0002.

## Context

ADR-0002 («Quest Start Is Global») описывает, что в момент старта Quest движок «открывает первый LevelProgress» и «запускает таймер первого уровня» для всех зарегистрированных команд сразу — то есть eager-создание `LevelProgress`.

Это прямо противоречит:
- `01-domain/progress.md`: «Первый LevelProgress создаётся в момент первого входа команды в Quest. Создание QuestProgress и создание первого LevelProgress являются разными событиями.»
- фактической реализации: `QuestProgressServiceImpl.enterQuest()` — единственное место, создающее первый `LevelProgress`, вызывается только явным действием команды («войти в квест»).

Расхождение обнаружено при проектировании планировщика (`03-architecture/scheduling.md`, Job 1).

## Decision

ADR-0002 амендируется: убирается требование eager-создания `LevelProgress` в момент старта Quest.

Job 1 планировщика (старт Quest) выполняет только:
1. Перевод Quest в `RUNNING`.
2. Создание `QuestProgress` для каждой `APPROVED`-регистрации (через существующий `questProgressService.createProgress()`).

`LevelProgress` создаётся лениво, при первом входе команды — модель `progress.md` и текущая реализация `enterQuest()` сохраняются без изменений.

Остальные положения ADR-0002 (глобальность старта, отсутствие преимущества позднего входа, единая временная шкала) остаются в силе — меняется только конкретный технический пункт про момент создания `LevelProgress`.

## Consequences

Преимущества:
- Не создаются «мёртвые» строки `LevelProgress` для команд, подтверждённых, но не зашедших в игру.
- Честность игрового времени сохраняется без eager-создания: `autoTransitionAt` для первого уровня считается от `Quest.startTime`/`QuestProgress.questStartedAt`, а не от `LevelProgress.openedAt` — это уже гарантирует отсутствие преимущества позднего входа.
- Job 1 не выполняет потенциально дорогую пакетную операцию создания `LevelProgress` для сотен команд синхронно — нагрузка размазывается по времени фактического входа команд.
- Согласованность документации: `progress.md`, ADR-0002 (после правки) и код теперь описывают одну и ту же модель.

Издержки: нет — решение устраняет расхождение, не вводит новый компромисс.
