# ADR-0019 — Target Audience And Game Format (Offline / Online)

## Status

Proposed — не решение, а формализация открытого вопроса. Требует продуктового решения, не может быть принято инженерной командой в одностороннем порядке.

## Context

`00-vision/product-vision.md` фиксирует, что не определены:
- целевая аудитория (закрытая платформа для организаторов vs открытая для любого зарегистрированного пользователя — `UserRole.AUTHOR` технически допускает оба варианта);
- поддерживаемый формат игры — офлайн (команда физически перемещается по городу, аналог классического Encounter) или онлайн (команда играет удалённо), или оба.

Модель данных сейчас не различает форматы явно — `QuestType` содержит только `SINGLE`/`TEAM` (состав участников), не формат проведения.

Это не техническое ограничение — это вопрос о том, что за продукт мы строим, требующий ответа от владельца продукта.

Блокирует принятие ADR-0013 (часовой пояс отображения `Quest.startTime`), т.к. правильное отображение времени прямо зависит от формата игры.

## Decision

**Решение не принято этим ADR.** Документ фиксирует вопрос и варианты, чтобы:
1. Не потерять эту зависимость (ADR-0013 явно ссылается на этот ADR как блокирующий).
2. Дать продукту готовую формулировку вопроса, а не заставлять инженерную команду формулировать его заново при следующей необходимости.

Варианты, требующие выбора:
- **Аудитория**: закрытая (организаторы, отбираемые вручную) vs открытая платформа (любой пользователь может стать автором).
- **Формат**: только офлайн, только онлайн, либо оба (с явным полем формата на Quest, определяющим поведение отображения времени и, возможно, других аспектов).

## Consequences

До принятия решения:
- ADR-0013 (часовой пояс) остаётся заблокированным.
- `06-nfr/requirements.md` (раздел «Часовые пояса») не может быть закрыт содержательно.

После принятия решения этот ADR должен быть обновлён (статус → Accepted, раздел Decision заполнен) или заменён новым ADR, ссылающимся на него как на Superseded.
