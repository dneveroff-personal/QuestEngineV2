# ADR-0019 — One Entity Model For All Game Formats (No Offline/Online Split)

## Status

Accepted

## Context

Открытый вопрос: нужно ли различать офлайн-квесты (команда физически перемещается по городу) и онлайн-квесты (команда играет удалённо) на уровне модели данных — например, отдельным `QuestType`/`GameFormat` или отдельными сущностями.

## Decision

Модель данных **не** различает офлайн и онлайн форматы. `QuestType` остаётся только `SINGLE`/`TEAM` (состав участников: одиночная или командная игра) — это единственное структурное деление.

Формат игры (офлайн/онлайн/гибрид) — вопрос **содержания**, которое пишет автор в описании/анонсе Quest (`Quest.content`/аналогичное текстовое поле), а не структуры данных. Процедура перехода по уровням, ввода кодов, автопереходов, подсказок — одинакова для любого формата.

## Consequences

Преимущества:
- Одна модель данных для всех форматов — меньше кода, меньше специальных случаев в валидации и API.
- Авторы не ограничены жёсткой типизацией — гибридные форматы (например, часть уровней офлайн, часть — дистанционные задания) не требуют обхода схемы.
- Соответствует принципу простоты, приоритетному для учебного проекта на данном этапе.

Издержки:
- Движок не может программно проверить консистентность содержания с заявленным форматом (например, предупредить автора, если Quest помечен как «офлайн», но не содержит указаний на локации) — это признанное ограничение, не решаемое на уровне схемы, полагается на добросовестность автора.

Разблокирует ADR-0013 (часовой пояс отображения времени) — раз формат не различается структурно, время всегда отображается единообразно, см. ADR-0013.
