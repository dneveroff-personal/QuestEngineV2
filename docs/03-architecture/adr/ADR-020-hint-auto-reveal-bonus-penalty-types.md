# ADR-0020 — Hint Model: Auto-Reveal, Regular/Bonus/Penalty Types

## Status

Accepted

## Context

При сверке документов обнаружено внутреннее расхождение, ранее не замеченное: `01-domain/level.md` (более ранний, оригинальный текст автора проекта) уже содержит раздел «Типы подсказок» с тремя типами — `Regular`/`Bonus`/`Penalty`, и утверждает, что подсказки «открываются автоматически через заданное автором время» (auto-reveal). При этом `01-domain/hint-progress.md` (написан позже, в рамках работы над документацией) трактовал и «auto-reveal vs manual-open», и «штрафует ли подсказка время» как полностью открытые вопросы — не заметив, что `level.md` уже фиксирует ответ на оба.

`Hint`-сущность в коде на данный момент не имеет поля `type` — раздел `level.md` описывает целевую модель, ещё не реализованную, а не текущее состояние кода (фраза «в текущей версии движка» в `level.md` относится к дизайну/спецификации, не к реализации).

## Decision

Принимается модель `level.md` как источник истины, `hint-progress.md` приводится в соответствие:

1. **Auto-reveal**: подсказка становится видимой команде автоматически по достижении `hintAvailableAt = LevelProgress.openedAt + Hint.delaySeconds`, без отдельного действия команды («открыть подсказку»). Действие команды не требуется и не предусмотрено.
2. **Три типа подсказки** (аналогично `CodeType`, для консистентности именования — см. ADR-0006):
   - `REGULAR` — не влияет на итоговое время.
   - `BONUS` — при показе команде начисляет бонусное время (`Hint.bonusPenaltySeconds`).
   - `PENALTY` — при показе команде начисляет штрафное время (`Hint.bonusPenaltySeconds`).
3. Поскольку показ автоматический (не решение команды), эффект `BONUS`/`PENALTY`-подсказки применяется **безусловно** в момент наступления `hintAvailableAt` — в отличие от `BONUS`/`PENALTY`-кода (который требует активного действия команды — ввода кода), здесь команда не может отказаться от эффекта.

Требуется добавить в модель данных: `Hint.type` (enum, аналог `CodeType`), `Hint.bonusPenaltySeconds` (Integer, nullable — обязателен только для `BONUS`/`PENALTY`).

## Consequences

Преимущества:
- Устранено внутреннее противоречие документации.
- Модель подсказок консистентна с уже принятой моделью кодов (ADR-0006, ADR-0007) — одинаковое именование, одинаковый принцип агрегации итогового времени.
- `HintProgress` упрощается: не нужно хранить `openedBy` (открытие не ручное) — только факт и момент показа.

Издержки:
- Требуется миграция схемы `hints` (новые колонки `type`, `bonus_penalty_seconds`).
- `01-domain/bonus-penalty.md` требует правки — появляется третий источник бонус/штраф-времени (auto-reveal подсказка) в дополнение к ручной корректировке автора и `BONUS`/`PENALTY`-коду.

Заменяет открытые вопросы 1 и 2 из первой версии `01-domain/hint-progress.md`. Вопрос «может ли автор открыть подсказку раньше срока вручную» остаётся открытым отдельно — не затрагивается этим решением.
