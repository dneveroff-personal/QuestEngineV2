# ADR-0021 — BONUS/PENALTY Hints Require Explicit Team Action ("Take"), Amends ADR-0020

## Status

Accepted — амендирует ADR-0020.

## Context

ADR-0020 приняло модель, где все типы подсказок (`REGULAR`/`BONUS`/`PENALTY`) показываются команде автоматически (auto-reveal) по достижении `hintAvailableAt`, без действия команды, и эффект `BONUS`/`PENALTY` применяется безусловно.

Владелец продукта уточнил: этого недостаточно для копирования механики Encounter. Нужен явный выбор команды — типичный кейс: неопытной команде, застрявшей на уровне, предлагается несколько штрафных подсказок (например, по 10 минут каждая), и команда должна **решить**, стоит ли жертвовать временем ради помощи, а не получать штраф принудительно вместе с подсказкой.

## Decision

Разделение по типу подсказки:

- **`REGULAR`** — поведение не меняется: auto-reveal по `hintAvailableAt`, без действия команды (Job 3 продолжает работать как раньше).
- **`BONUS`/`PENALTY`** — auto-reveal отменяется. По достижении `hintAvailableAt` подсказка становится **доступной для взятия** (вычисляемый факт, не требует записи в БД), но команда должна явно вызвать действие **«взять подсказку»**, чтобы увидеть содержимое и получить/понести эффект.

### Что видно команде до взятия (для BONUS/PENALTY)

- Факт, что подсказка доступна (`hintId`, `orderIndex`).
- **Тип** — `BONUS` или `PENALTY` (команда знает, поощрение это или наказание).
- **НЕ видно**: точное значение `bonusPenaltySeconds` и содержимое (`content`) — команда принимает решение вслепую относительно конкретной цены/содержания, зная только знак эффекта.

### Что происходит при взятии

- Создаётся `HintProgress` (как и раньше — факт показа/взятия, `shownAt`).
- Эффект `bonusPenaltySeconds` применяется (в момент, когда эффект будет реализован — см. `roadmap/backlog.md`, п. 6, ADR-0007 — сам факт взятия уже фиксируется этим ADR, применение к итоговому времени остаётся отдельной задачей).
- Взять можно **в любой момент**, пока `LevelProgress` находится в статусе `ACTIVE` (не обязательно сразу в момент появления доступности) — команда может обдумать решение, не теряя окно.
- Взятие идемпотентно: повторный вызов для уже взятой подсказки не создаёт дубликата и не повторяет эффект (тот же паттерн, что и в `CodeSubmission`/`createFirstLevelProgress`).

### Кто может взять

Любой участник команды (тот же принцип, что и для ввода кодов, `01-domain/code-submission.md`) — не только капитан.

## Consequences

Преимущества:
- Соответствует референсной механике Encounter — осознанный выбор команды, а не навязанный эффект.
- `REGULAR`-подсказки остаются максимально простыми (не требуют лишнего действия там, где выбирать нечего — подсказка бесплатна).

Издержки:
- Требуется новый эндпоинт (`POST .../hints/{hintId}/take`) и изменение формы ответа `GET .../hints` (нужно различать «доступна, не взята» от «взята» состояния, с разным набором видимых полей).
- `HintRevealScheduler` (Job 3) должен фильтровать по типу — auto-reveal применяется только к `REGULAR`.
- Отменяет пункт 3 ADR-0020 («эффект применяется безусловно») для `BONUS`/`PENALTY` — эффект теперь применяется только при явном взятии. Пункт 3 ADR-0020 остаётся в силе только для будущего REGULAR (у REGULAR эффекта нет по определению, пункт неприменим) — фактически пункт 3 ADR-0020 полностью заменяется этим ADR для типов, где он был содержателен.
