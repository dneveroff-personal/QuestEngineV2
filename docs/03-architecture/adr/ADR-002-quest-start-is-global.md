# ADR-0002 — Quest Start Is Global

## Status

Accepted — частично амендирован ADR-0008 (см. ниже, раздел Decision больше не требует eager-создания LevelProgress).

## Context

Quest имеет заранее определённое время начала.

В момент старта соревнования все команды должны находиться в одинаковых условиях.

Время прохождения зависит исключительно от времени старта Quest, а не от момента открытия приложения игроками.

Это полностью соответствует механике игр семейства Encounter.

## Decision

В момент наступления времени начала Quest считается стартовавшим независимо от действий игроков.

Движок автоматически:

- переводит Quest в состояние RUNNING;
- создаёт QuestProgress для всех зарегистрированных команд;
- открывает первый LevelProgress;
- запускает таймер первого уровня.

Если команда открывает приложение позже, она получает текущее состояние уже идущего QuestProgress.

## Example

```
21:00:00

Quest started

↓

QuestProgress(Team A)

↓

QuestProgress(Team B)

↓

QuestProgress(Team C)

↓

LevelProgress #1 created

↓

Timers started

↓

21:05

Team B entered Quest

↓

Получает уже идущий первый уровень
```

## Consequences

Преимущества:

- отсутствует преимущество позднего входа;
- единая временная шкала для всех участников;
- простая реализация таймеров;
- прозрачная статистика;
- полное соответствие правилам соревнования.

## Amendment (ADR-0008)

Пункты «открывает первый LevelProgress» и «запускает таймер первого уровня» из раздела Decision выше — **отменены** ADR-0008. `LevelProgress` создаётся лениво, при первом входе команды, а не eager-но при старте Quest. Честность игрового времени при этом сохраняется: `autoTransitionAt` первого уровня считается от времени старта Quest, а не от момента создания `LevelProgress`. Остальные положения этого ADR остаются в силе без изменений. Подробности и обоснование — в ADR-0008.
