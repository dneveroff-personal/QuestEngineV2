# ADR-0005 — Level Completion Model: Required Codes, Synonyms, Threshold

## Status

Accepted

## Context

Первоначальная формулировка `01-domain/progress.md` («команда ввела необходимое количество правильных кодов») была неоднозначна. Первая версия этого ADR предлагала упрощённый вариант (один любой MAIN-код завершает уровень) — отклонён как не соответствующий реальным правилам движка. Вторая версия ввела термин «группа кодов» для обозначения синонимов одного ответа — тоже отклонён: термин путал (непонятно, что закрывает ввод — «код» или «группу»). Ниже — финальная терминология и модель, зафиксированные владельцем продукта.

## Decision

### Терминология (важно, чтобы не путаться)

- **Код** (`Code`, требуемый) — логический правильный ответ уровня. У уровня может быть несколько таких кодов.
- **Синоним** — конкретный принятый вариант написания этого кода (например, разные допустимые формулировки одного ответа). Технически каждый синоним — отдельная строка `Code` с типом `MAIN`, несколько синонимов одного кода объединены общим `Code.codeIndex`. Ввод **любого одного** синонима засчитывает **весь код** (не «группу» — слово «группа» не используется).
- `BONUS`/`PENALTY`-коды не являются «требуемыми кодами» уровня и не участвуют в этой нумерации (`codeIndex` для них не применяется).

### Таксономия типов уровня (по составу кодов и наличию автоперехода)

| # | Коды | Автопереход | Название | Смысл |
|---|---|---|---|---|
| 1 | нет | нет | **Аномальный** | Физически непроходим. Не должен встречаться в опубликованном Quest. |
| 2 | нет | да | **Заглушка по времени** | Нет задания на ввод кода — команда обязана находиться на уровне заданное время. |
| 3 | 1 код (без синонимов) | нет | **Заглушка по коду** | Только ввод единственного кода, либо DNF. |
| 4 | 1 код (возможно с синонимами) | да | **Обычный уровень** | Наиболее частый случай: код или автопереход, что раньше. |
| 5 | несколько кодов (у каждого возможны синонимы) | не важно | **Составной уровень** | Несколько независимых заданий, автор задаёт порог. |

Валидация при публикации Quest должна отклонять Тип 1 как ошибку конфигурации автора.

### Пример

```
Level "Три вопроса"
  Код #1 ("любой цвет радуги"): синонимы "красный", "оранжевый", ..., "фиолетовый"  — codeIndex=1, type=MAIN
  Код #2 ("любой месяц года"): синонимы "январь", ..., "декабрь"                    — codeIndex=2, type=MAIN
  Код #3 ("первая буква алфавита"): синоним "а"                                     — codeIndex=3, type=MAIN
  Код "секретный бонус"                                                              — type=BONUS (не участвует в codeIndex)
```

### Порог прохождения составного уровня

Автор задаёт **порог** — сколько из требуемых кодов уровня нужно решить, необязательно все. Порядок решения не важен: команда A решает коды 1 и 2, команда B — коды 2 и 3, обе проходят уровень при пороге 2 из 3.

Технически: `Level.requiredMainCodesCount` (nullable Integer) — `null` означает «требуются все коды уровня» (для Типа 4 с одним кодом это тривиально совпадает с «единственный код»); число `N` — уровень завершается, как только количество **различных решённых кодов** (различных `codeIndex` с зачтённым синонимом) достигает `N`.

### Прогресс, показываемый команде (решено)

Во время игры команда видит текст вида **«Осталось ввести {remaining} из {requiredMainCodesCount} кодов»** (где `requiredMainCodesCount` — порог, или общее число кодов уровня, если порог не задан; `remaining = requiredMainCodesCount − количество уже решённых кодов`). Показывается именно «осталось», а не «решено» — команде важнее знать, сколько ещё нужно, чем сколько уже сделано.

## Consequences

Преимущества:
- Термин «код»/«синоним» без промежуточного понятия «группа» — устраняет путаницу (что именно «закрывается» вводом: сам код, а не абстрактная группа).
- Модель покрывает все реальные сценарии, включая составные уровни с частичным порогом.
- Явная таксономия (5 типов) даёт основу для валидации контента автора.

Издержки:
- `Code` содержит поле `codeIndex`, `Level` — поле `requiredMainCodesCount`. Реализовано (`0.5.18`+): миграции `V7`/`V9`, сущности, DTO, сервисы.
- `LevelProgress`/`CodeSubmission` должны агрегировать «сколько различных кодов (по `codeIndex`) уже решено» для проверки порога и для сообщения об оставшемся количестве.

Заменяет собой оба предыдущих варианта этого ADR. Детализация игровых правил ввода кода — `01-domain/code-submission.md`.
