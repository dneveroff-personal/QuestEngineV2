# ADR-0005 — Level Completion Model: Main Code Groups, Synonyms, Threshold

## Status

Accepted

## Context

Первоначальная формулировка `01-domain/progress.md` («команда ввела необходимое количество правильных кодов») была неоднозначна. Первая версия этого ADR предлагала упрощённый вариант (один любой MAIN-код завершает уровень) — этот вариант отклонён как не соответствующий реальным правилам движка. Ниже — правильная модель, зафиксированная владельцем продукта.

## Decision

### Таксономия типов уровня (по составу кодов и наличию автоперехода)

Комбинация «есть ли коды» × «есть ли автопереход» даёт 4 содержательных типа уровня плюс один аномальный:

| # | Коды | Автопереход | Название | Смысл |
|---|---|---|---|---|
| 1 | нет | нет | **Аномальный** | Физически непроходим — ни ввести код, ни дождаться автоперехода. Не должен встречаться в опубликованном Quest, допустим только в процессе редактирования. |
| 2 | нет | да | **Заглушка по времени** | Нет задания на ввод кода — команда обязана находиться на уровне заданное время (сюжетная вставка, переезд, ожидание). Проходится только автопереходом. |
| 3 | 1 main-код (без синонимов) | нет | **Заглушка по коду** | Пройти можно только введя единственный код, ждать нечего — либо ввести код, либо не пройти уровень вовсе (DNF). Редкий, но допустимый случай. |
| 4 | 1 main-код (возможно с синонимами) | да | **Обычный уровень** | Наиболее частый случай в квесте: либо команда решает задание и вводит код (или один из его синонимов) до истечения времени, либо срабатывает автопереход. |
| 5 | несколько main-кодов (каждый — возможно с синонимами) | не важно | **Составной уровень** | Несколько независимых заданий на одном уровне, автор задаёт порог — сколько из них нужно решить, необязательно все. |

Валидация при публикации Quest должна отклонять Тип 1 (аномальный) как ошибку конфигурации автора — это не runtime-правило, а проверка целостности контента при переходе `DRAFT → REGISTRATION`/публикации уровня.

### Main-коды и синонимы

Один смысловой правильный ответ уровня («main-код») может иметь несколько равнозначных текстовых вариантов написания — «синонимов». Пример: задание «код прохождения — любой цвет радуги» — физически один main-код («любой цвет радуги»), но с 7 синонимами («красный», «оранжевый», ..., «фиолетовый»). Ввод **любого одного** синонима засчитывает этот конкретный main-код как решённый.

Технически (изменение схемы данных, детализация — при реализации `CodeSubmission`): вводится группировка кодов внутри Level — коды с одним и тем же `groupIndex` являются синонимами одного main-кода. `BONUS`/`PENALTY`-коды в группировку не входят (они не являются вариантами ответа, см. `01-domain/bonus-penalty.md`).

```
Level "Радуга"
  code_group #1 ("любой цвет радуги"): "красный", "оранжевый", "жёлтый", "зелёный", "голубой", "синий", "фиолетовый"  — type=MAIN
  code "секретный бонус"                                                                                              — type=BONUS
```

### Порог прохождения составного уровня

Уровень может содержать несколько независимых main-кодов (несколько групп синонимов). Автор задаёт **порог** — сколько из этих групп нужно решить, необязательно все.

Пример: 3 main-кода на уровне (цвет радуги / месяц года / первая буква алфавита), порог = 2. Команда A вводит «синий», «декабрь» — уровень пройден (2 из 3, третий не требуется). Команда B вводит «а», «март» — тоже пройден, в другом сочетании. Порядок ввода групп не имеет значения — команда сама решает, какие 2 из 3 заданий решать.

Технически: `Level.requiredMainCodesCount` (nullable Integer) — если `null`, требуются **все** группы main-кодов на уровне (это значение по умолчанию, соответствует Типу 4 — один main-код, где «все» и «один» совпадают). Если задано число — уровень завершается, как только количество **различных** решённых групп (различных `groupIndex` с зачтённым синонимом) достигает этого числа.

## Consequences

Преимущества:
- Модель покрывает все реальные сценарии Encounter-подобных квестов, включая составные уровни с частичным порогом — без этого движок не мог бы воспроизвести распространённую механику «выберите N из M заданий».
- Синонимы решают частую проблему ввода (опечатки в написании, разные допустимые формулировки одного ответа) без необходимости заводить отдельный уровень на каждый вариант формулировки.
- Явная таксономия (5 типов) даёт основу для валидации контента автора — можно программно предупредить о Типе 1 (аномальном) уровне при редактировании.

Издержки:
- Модель данных `Code` требует нового поля `groupIndex`, `Level` — нового поля `requiredMainCodesCount`. Требуется миграция схемы.
- `LevelProgress`/`CodeSubmission` должны уметь агрегировать «сколько различных групп уже решено» для проверки порога — чуть сложнее, чем простой счётчик правильных попыток.

Заменяет собой упрощённый вариант («любой один MAIN-код»), ранее предложенный этим же ADR и отклонённый.

Детализация игровых правил ввода кода (нормализация, антибрутфорс, идемпотентность) — без изменений, см. `01-domain/code-submission.md`, который обновлён этим решением в части критерия завершения уровня.
