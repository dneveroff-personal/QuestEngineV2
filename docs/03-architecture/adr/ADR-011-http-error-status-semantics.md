# ADR-0011 — HTTP Error Status Semantics: 403 vs 404 vs 409

## Status

Accepted

## Context

`GlobalExceptionHandler` содержит два семантических несоответствия, найденных при сверке с `04-api/conventions.md`:

1. `ForbiddenOperationException` (название подразумевает `403`) возвращает `409 Conflict`. В коде это исключение используется одновременно и для «нет прав» (`validateQuestAuthor`), и для «состояние не позволяет» (`validateApprovedTeamsLimit`, `validateProgressWaiting`) — то есть под одним именем скрыты два разных смысла.
2. `IllegalArgumentException`/`IllegalStateException` массово используются и для «сущность не найдена» (`"Квест не найден: " + questId"`), и для «некорректный ввод» — но всегда маппятся на `409`.

Без разведения семантики клиентский код (веб/мобильное приложение) не может программно отличить «у меня нет прав» от «уже нельзя» от «не существует» — только по тексту `detail`, что хрупко (текст на русском языке, не предназначен для программной обработки, см. также открытый вопрос локализации в `06-nfr/requirements.md`).

## Decision

Вводится три конкретных исключения с закреплённой семантикой вместо смешанного использования `ForbiddenOperationException`/`IllegalArgumentException`/`IllegalStateException`:

| Исключение | HTTP-статус | Смысл |
|---|---|---|
| `AccessDeniedException` (или переименованный `ForbiddenOperationException`, используемый только для этого смысла) | `403 Forbidden` | У пользователя нет прав на действие в принципе (роль/владение) |
| `ResourceNotFoundException` | `404 Not Found` | Сущность с данным ID не существует |
| `ConflictException` (текущий `ForbiddenOperationException` для этого смысла, либо новое имя) | `409 Conflict` | Права есть, но текущее состояние ресурса не позволяет действие |

Существующие места использования `IllegalArgumentException`/`IllegalStateException` для «не найдено» переводятся на `ResourceNotFoundException`.

## Consequences

Преимущества:
- Клиентский код может программно различать три класса ошибок по статусу, не парся текст.
- Устраняет найденное несоответствие имени класса и фактического статуса.

Издержки:
- Требует рефакторинга существующего кода сервисов (замена типа выбрасываемого исключения в местах валидации) — не блокирует MVP функционально, но должно быть сделано до роста числа таких мест (сейчас уже используется в 6+ сервисах).

Задача зафиксирована в `roadmap/backlog.md` как блокер приоритета 5 (не 0 — не мешает базовому функционированию, но откладывать нежелательно).
