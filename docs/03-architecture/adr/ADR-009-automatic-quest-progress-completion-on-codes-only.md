# ADR-0009 — QuestProgress Completes Automatically Only When Last Level Finished By Codes

## Status

Proposed — затрагивает игровой дизайн (что считается «честным» финишем), требует подтверждения продукта.

## Context

`01-domain/progress.md` описывает завершение `QuestProgress` статусом `FINISHED` «после прохождения последнего уровня», не уточняя, относится ли это только к прохождению кодами, или включает и случай, когда последний уровень завершился по автопереходу (истёк таймер, команда не успела).

Текущая реализация `finishProgress()` требует ручного вызова автором для каждой команды и не привязана к событию завершения уровня — на практике сейчас автоматического завершения нет вообще, ни в каком случае.

Различие важно: в соревновательных играх этого класса принято различать «дошла своими силами» от «не успела» — это влияет на честность и прозрачность итогового результата. Полный разбор — `03-architecture/scheduling.md`, Job 2.

## Decision

**Вариант A**: `QuestProgress` переводится в `FINISHED` автоматически (планировщиком, Job 2), только если последний уровень завершён способом `CODES` (команда ввела верный код своими силами).

Если последний уровень завершился по `AUTO_TRANSITION` (время истекло, команда не прошла) — `QuestProgress` **не** переводится в `FINISHED` автоматически. Судьбу такой команды (обычно `DNF`) определяет автор вручную при финальном завершении Quest (шаг 13 `02-processes/quest-lifecycle.md`).

Ручной `finishProgress()` сохраняется как инструмент автора для форс-мажорных случаев (например, технический сбой у команды, зафиксированное на месте прохождение без возможности ввести код онлайн), а не как основной путь завершения.

## Consequences

Преимущества:
- Честное различение результатов в статистике — соответствует практике Encounter-подобных игр.
- Автоматизация основного случая (успешное прохождение) без потери ручного контроля над пограничными случаями.

Издержки:
- Команды, не прошедшие последний уровень по таймеру, остаются в `RUNNING` до конца Quest — требует, чтобы UI/статистика корректно отображали это промежуточное состояние, а не трактовали как ошибку.

**Требует подтверждения продукта до реализации Job 2** — если игровой дизайн решит не различать эти два случая (Вариант B — оба пути завершают QuestProgress автоматически), решение нужно пересмотреть.
