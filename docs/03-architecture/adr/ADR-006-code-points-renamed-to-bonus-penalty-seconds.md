# ADR-0006 — Code.points Renamed To bonusPenaltySeconds, Stored In Seconds

## Status

Accepted

## Context

`Code.points` (Integer) не имеет описанной единицы измерения ни в коде, ни в документации. Название поля («points»/«очки») вводит в заблуждение — движок не поддерживает и не планирует режим scoring по очкам, только время прохождения (см. `01-domain/statistics-ranking.md`).

Остальные временные поля системы (`Level.timeoutSeconds`, `Hint.delaySeconds`) уже хранятся в секундах — рассинхронизация единиц между соседними полями одной модели создаёт риск ошибок при разработке (перепутать секунды с минутами).

Полный разбор — `01-domain/bonus-penalty.md`.

## Decision

Поле `Code.points` переименовывается в `Code.bonusPenaltySeconds`, хранится в секундах, консистентно с остальными временными полями модели.

Отображение в UI (если потребуется в минутах для удобства автора) — ответственность слоя представления, не модели данных.

Требуется миграция схемы (`ALTER TABLE codes RENAME COLUMN points TO bonus_penalty_seconds`) и обновление DTO/сервисов.

## Consequences

Преимущества:
- Единообразие единиц измерения времени по всей модели.
- Устранена двусмысленность названия поля.

Издержки:
- Требуется миграция схемы и правка всех мест, использующих `Code.points` (на момент принятия решения — только CRUD-слой, `CodeSubmission` ещё не реализован, поэтому цена изменения минимальна).
