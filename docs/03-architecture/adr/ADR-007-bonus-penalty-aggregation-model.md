# ADR-0007 — Final Time Is An Aggregate Of Manual Adjustments And Code-Triggered Effects

## Status

Accepted

## Context

До этого решения в документации существовало два независимых, не связанных друг с другом описания источника бонусного/штрафного времени:

1. `01-domain/statistics-ranking.md`: бонус/штраф начисляет только автор вручную.
2. Модель данных `Code` уже содержит `CodeType.BONUS`/`CodeType.PENALTY` — эффект начисляется автоматически при вводе кода командой.

Оба источника реальны и не противоречат друг другу по смыслу — это независимые каналы одного и того же эффекта. Требуется единая модель, объединяющая оба, вместо двух несогласованных описаний. Полный разбор — `01-domain/bonus-penalty.md`.

## Decision

Вводится сущность `ManualTimeAdjustment` для ручных начислений автора: обязательные поля `questProgress`, `type` (BONUS/PENALTY), `seconds`, `reason` (не nullable), `createdBy`, `createdAt`, опционально `revokedAt`/`revokedBy` (soft-revoke, без физического удаления).

Итоговое время `QuestProgress` вычисляется как агрегат (сумма), а не денормализованное перезаписываемое поле:

```
finalTime =
    фактическое игровое время
  − Σ секунд по зачтённым CodeSubmission типа CORRECT_BONUS
  + Σ секунд по зачтённым CodeSubmission типа CORRECT_PENALTY
  − Σ секунд по неотозванным ManualTimeAdjustment типа BONUS
  + Σ секунд по неотозванным ManualTimeAdjustment типа PENALTY
```

Ручная корректировка отзывается (soft-revoke) только до перевода Quest в `FINISHED`; после — становится неизменным историческим фактом.

## Consequences

Преимущества:
- Оба источника учитываются единообразно, без конфликта.
- Полный аудит начислений (обязателен для соревновательной механики — см. также `05-security/threat-model.md`, раздел «Аудируемость административных действий»).
- Отсутствие lost-update гонки: агрегация суммированием при чтении/пересчёте, а не инкремент изменяемого поля (см. `02-processes/concurrency-scenarios.md`, Сценарий 4).

Издержки:
- Требует пересчёта итогового времени при каждом изменении одного из слагаемых — дороже, чем чтение одного денормализованного поля, но пренебрежимо на ожидаемых объёмах (см. `06-nfr/requirements.md`).
