# ADR-0012 — Listing Endpoints Return Paginated Response With Metadata

## Status

Accepted

## Context

Ряд эндпоинтов (`GET /api/users/search`, `GET /api/teams/search`) уже принимают `Pageable` на вход (параметры `page`/`size`/`sort` используются для отбора нужной страницы данных из БД), но методы сервисов возвращают `List<T>`, а не `Page<T>`. Клиент не получает метаданные — общее количество записей, общее количество страниц — и не может отличить «это все записи» от «есть ещё». Найдено при написании `04-api/conventions.md`.

## Decision

Все listing-эндпоинты, принимающие параметры пагинации, возвращают обёртку с метаданными вместо голого массива:

```json
{
  "content": [...],
  "page": 0,
  "size": 20,
  "totalElements": 143,
  "totalPages": 8
}
```

Используется собственная DTO-обёртка (`PageResponse<T>`), а не проброс `org.springframework.data.domain.Page` напрямую в контракт API — чтобы не завязывать публичный контракт на конкретную реализацию пагинации Spring Data и сохранить свободу заменить механизм пагинации внутри без изменения контракта.

## Consequences

Преимущества:
- Клиент может корректно реализовать постраничную навигацию (кнопка «далее», индикатор общего количества).
- Публичный контракт не зависит от внутренней реализации (Spring Data `Page` может измениться или быть заменена без breaking change для клиентов).

Издержки:
- Требует правки сигнатур существующих сервисных методов и соответствующих тестов (`*ServiceImplTest`, `*ControllerTest`) для затронутых ресурсов — некритично, локализовано в паре мест на данный момент.
