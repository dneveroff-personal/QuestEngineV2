# ADR-0009 — QuestProgress Completes Automatically, Regardless Of How The Last Level Ended

## Status

Accepted

## Context

Первая версия этого ADR предлагала различать «честный» финиш (последний уровень пройден кодами) от «непройденного» (последний уровень завершился по автопереходу) — с идеей не переводить `QuestProgress` в `FINISHED` автоматически во втором случае. Это решение отклонено владельцем продукта: разницы быть не должно.

## Decision

`QuestProgress` переводится в `FINISHED` автоматически, как только завершается последний Level команды — **независимо** от того, как именно он завершился: вводом кодов (`CODES`) или автопереходом по таймеру (`AUTO_TRANSITION`).

И то, и другое — законный, штатный способ завершить уровень (см. таксономию уровней в `01-domain/code-submission.md`/ADR-0005 — заглушки, например, вообще проходятся только автопереходом). Различать их для целей завершения `QuestProgress` не нужно: команда либо прошла все уровни, либо нет (и тогда получит `DNF`, если вообще не начинала/не закончила квест — это отдельный, независимый статус, не связанный со способом прохождения последнего уровня).

Реализация уже частично существует в коде и корректно следует этому правилу: `QuestProgressServiceImpl.completeLevel()` при отсутствии следующего Level безусловно переводит `QuestProgress` в `FINISHED` — без ветвления по способу завершения предыдущего уровня. Остаётся довести до конца: сейчас этот метод вызывается только вручную (нет эндпоинта, нет вызова из планировщика для случая `AUTO_TRANSITION` последнего уровня) — после реализации Job 2 (`03-architecture/scheduling.md`) он должен вызываться единообразно из обоих путей завершения уровня.

Ручной `finishProgress()` (существующий в коде метод) сохраняется как инструмент автора для форс-мажорных случаев, не как основной путь завершения.

## Consequences

Преимущества:
- Простая, предсказуемая модель — одно правило без исключений.
- Совпадает с уже написанной реализацией `completeLevel()` — не требует переделки существующего кода, только его правильное подключение к обоим путям завершения последнего уровня (коды и планировщик).

Издержки: нет — упрощение по сравнению с отклонённым вариантом.

Реализация: `03-architecture/scheduling.md`, Job 2 — должен вызывать тот же путь завершения (`QuestProgressServiceImpl.completeLevel()`), что и ввод кода, без ветвления по причине завершения уровня.
