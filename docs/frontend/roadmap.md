# Frontend — Задачи

Источник задач — спеки в этой папке (`screens.md`, `information-architecture.md`,
`user-flows.md`, `architecture.md`), а не история реализации. Состояние
backend подробно — `docs/roadmap/backlog.md`, здесь только вывод: что это
значит для фронта.

Статусы: 🟢 можно делать сейчас · 🔴 ждёт backend

---

## Реализовано

Auth (login/register), Home, QuestDetail + регистрация команды, Team
(создание/поиск/заявки/приглашения/передача капитанства/выход),
Author-CRUD (Quest/Level/Hint/Code, рассмотрение заявок), Game Mode
(вход, ввод кода, показанные подсказки — без содержимого уровня, см.
ниже), Profile (личные данные, авторские квесты).

Тестами покрыто: unit (`jwt`, `errors`, `format`) + по одному component-тесту
на сложную логику в каждой feature. Дальше — расширять по той же схеме
(раздел ниже).

## 🟢 Можно делать сейчас

| Задача | Экран (спека) | Детали |
|---|---|---|
| **Home и QuestDetail — сделать публичными** | `screens.md` §1, §2 | Спека прямо требует доступ без авторизации ("доступна без авторизации" / "доступна... неавторизованным пользователям"). Сейчас обе страницы за `ProtectedRoute` вместе со всем остальным приложением. Нужно вынести из-под общей защиты, оставить действия (регистрация, вход в игру) требующими авторизации точечно. |
| **Author — группировка по статусу** | `screens.md` §6 | Спека: "созданные / в разработке / завершённые" — сейчас `AuthorQuestsPage` показывает плоский список со статусом в строке. Сгруппировать в разделы. |
| **Тесты остальных компонентов** | — | По той же схеме, что уже применена: `teams` (`CreateTeamForm`, `SearchTeamsForm`, `TeamManagementPanel`, `JoinRequestsPanel`), `authoring` (`QuestForm`, `LevelsEditor`, `HintsPanel`, `CodesPanel`, `RegistrationReviewPanel`), `gameplay` (`ShownHintsList`). |
| **Аудит доступности** | `architecture.md` §23 | Клавиатурная навигация, `aria-label` для icon-only controls. Ни разу не проходили целенаправленно. `CodesPanel`/`CodeSubmitForm` — известный пробел (инпуты без `<label>`, только `placeholder`). |

## 🔴 Ждёт backend

| Задача | Экран (спека) | Чего не хватает |
|---|---|---|
| **Игровой экран: текущий уровень, содержимое, таймер** | `screens.md` §9 | `LevelProgressResponse` не отдаётся ни одним endpoint'ом. Приоритет №1 — без этого игровой экран показывает только слепой ввод кода. |
| **Statistics целиком** | `screens.md` §10 | Backend-пакет `statistic/` пуст. |
| **MyQuests: "Текущие"/"Прошедшие", результат, место** | `screens.md` §3 | Нет обратного endpoint'а "квесты команды" + нет Statistics для результата/места. Сейчас — временный обходной список только предстоящих. |
| **QuestDetail: автор квеста** | `screens.md` §2 | `QuestResponse` не отдаёт `authorId`/`authorName`. |
| **QuestDetail/Editor: макс. команд, стоимость участия** | `screens.md` §2, §7, §8 | Таких полей нет в домене вообще (не только в DTO) — нужна доработка модели `Quest` на backend, не только API. |
| **Team: изменение названия** | `screens.md` §4 | Нет `PUT`/`PATCH` на команду. |
| **Team/Profile: история, статистика, результаты игр** | `screens.md` §4, §5 | Зависит от Statistics. |
| **Author: ручные штрафы/бонусы** | `screens.md` §8 | `bonuspenalty/` — есть сервисный слой, нет контроллера (в разработке). |
| **Profile: email, дата регистрации напрямую** | `screens.md` §5 | Нет `GET /api/users/me`; сейчас — обходной резолв через поиск, см. `useMyResolvedUser`. |
| **Auth: access+refresh** | ADR-0015 | Backend всё ещё на модели одного JWT на 24ч. |

Подробности и ссылки на конкретный backend-код по каждому пункту — в
`docs/roadmap/backlog.md`.
