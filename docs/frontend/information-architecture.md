# Frontend Information Architecture

## 1. Общая структура

Главная страница является основной точкой входа для любого пользователя.

После авторизации пользователь видит:

- текущие квесты;
- предстоящие квесты;
- основную навигацию.

Набор пунктов меню зависит от возможностей пользователя.

---

## 2. Главное меню игрока

Базовое меню доступно всем пользователям, участвующим в командах.

```text
Главная
│
├── Мои квесты
│
├── Команда
│
└── Профиль
```

### Главная

Главная страница приложения.

Содержит:
- текущие квесты;
- предстоящие квесты;
- краткую информацию о доступных играх;
- переход к странице конкретного квеста.


#### Карточка квеста

До регистрации команды и после регистрации отображается одна и та же
основная информация о Quest.

Публичная информация:
- название;
- описание;
- дата и время начала;
- тип квеста;
- автор;
- максимальное количество команд;
- стоимость участия, если указана;
- список команд, подавших заявку;
- список команд, подтверждённых автором.

Для пользователя также отображается текущее состояние его команды
относительно данного Quest.


#### Действия команды

Действия зависят от состояния регистрации команды.

1. Команда ещё не подала заявку
Доступно:
- Подать заявку

2. Заявка подана, но не подтверждена
Отображается:
- Заявка отправлена

Команда может отказаться от участия до момента подтверждения автором.

3. Заявка подтверждена

Команда считается принятой в игру.

До начала Quest:
- Участие подтверждено
- Ожидание начала игры 

После начала Quest для подтверждённой команды становится доступно
действие:
- Войти в игру
- Команда не подтверждена

Команда не получает доступа к QuestProgress.

Даже после наступления времени старта игры она не может начать прохождение,
пока автор не подтвердит её участие.

Автор может подтвердить команду и после фактического начала Quest.

--- 

### Игрок команды

Доступ к игровому режиму имеют игроки команды, которая:
 - подала заявку;
 - была подтверждена автором;
 - имеет созданный QuestProgress;
 - находится в состоянии, позволяющем войти в игру.

Игровой интерфейс не является частью публичной страницы Quest.

Переход:
```text
Quest
  │
  ▼
Войти в игру
  │
  ▼
QuestProgress
  │
  ▼
LevelProgress
```

Кнопка Войти в игру является точкой перехода из обычного интерфейса
приложения в игровой режим.

---

### Мои квесты

Содержит историю участия пользователя в квестах.

Разделяется на:
- текущие;
- предстоящие;
- завершённые.

Для завершённых игр пользователь может просматривать:
- таблицу результатов квеста;
- статистику;
- мониторинг ввода кодов своих или всех команд (если автор разрешил)


### Команда

Страница текущей команды пользователя.

Для обычного участника:
- название команды;
- капитан;
- список участников;
- информация о команде;
- статистика команды (список игр).

Для капитана дополнительно доступны операции управления командой,
предусмотренные backend/domain-документацией.

Капитан не является отдельной глобальной ролью пользователя.

Капитанство определяется принадлежностью пользователя к команде и его
ролью внутри команды.

### Профиль

Личный профиль пользователя.

Содержит:
- личную информацию;
- историю участия в играх;
- результаты;
- статистику;
- послужной список игр;
- информацию об авторстве квестов, если пользователь является автором.


## 3. Автор

Автор получает базовое меню игрока и дополнительный раздел:

```text
Главная
│
├── Мои квесты
├── Команда
├── Профиль
│
└── Авторская
```


### Авторская

Отдельный раздел управления авторскими квестами.

Содержит:
- созданные квесты и управление ими;
- квесты в процессе создания и управление ими;
- создание нового квеста.

Для каждого квеста автор может перейти в редактор.

Условная структура:

```text
Авторская
│
├── Мои квесты
│   ├── Черновики
│   ├── Предстоящие
│   ├── Текущие
│   └── Завершённые
│
└── Создать квест
```

Фактические статусы и доступные операции определяются backend/domain
спецификацией.


## 4. Администратор

Администратор видит все варианты меню.

```text
Главная
│
├── Мои квесты
├── Команда
├── Профиль
├── Авторская
└── Администрирование
```

Административный раздел будет определён отдельно.


## 5. Игровой режим

Во время прохождения Quest пользователь не должен видеть обычную
навигацию приложения.

Игровой интерфейс является отдельным режимом.

```text
Application
│
├── обычный режим
│   ├── Главная
│   ├── Мои квесты
│   ├── Команда
│   ├── Профиль
│   └── Авторская
│
└── игровой режим
    └── QuestProgress
        └── LevelProgress
```

Главный принцип игрового режима:

Пользователь должен заниматься игрой, а не навигацией по приложению.

На игровом экране допускаются только необходимые игровые действия:
- просмотр задания;
- ввод кода;
- просмотр подсказок;
- отображение таймера;
- просмотр текущего состояния;
- переход к статистике;
- выход из игры/переход из игрового режима.


## 6. Роли и интерфейс

Frontend использует backend как источник истины для прав пользователя.
(смотри докуменацию по backend)

Интерфейс определяется не только глобальной ролью.

Например:

PLAYER + MEMBER
PLAYER + CAPTAIN
AUTHOR + MEMBER
AUTHOR + CAPTAIN
ADMIN + CAPTAIN

Автор одновременно может быть капитаном команды.

Администратор может одновременно участвовать в команде и иметь
капитанские права.

Frontend не должен считать эти состояния взаимоисключающими.


## 7. Правило отображения действий

Frontend показывает пользователю только те действия, которые имеют смысл
в текущем контексте.

Например:
```text
обычный участник
    → просмотр команды

капитан
    → просмотр + управление командой

автор
    → просмотр + управление авторскими квестами

администратор
    → все доступные административные функции
```

Это улучшает UX, но не заменяет backend authorization.

Backend всегда повторно проверяет право выполнения операции.
