# ADR-0001 - Naming of runtime entities

## Status

Accepted

---

## Context

Quest Engine содержит два типа сущностей.

### Статические

Это объекты, создаваемые автором квеста.

Они являются шаблоном игры и никогда не изменяются во время прохождения.

Примеры:

- Quest
- Level
- Code
- Hint

---

### Runtime

После начала игры каждая команда получает собственное состояние прохождения.

Эти объекты постоянно изменяются:

- текущий уровень;
- найденные коды;
- использованные подсказки;
- штрафы;
- время прохождения.

Необходимо выбрать единое название для подобных сущностей.

---

## Рассмотренные варианты

### QuestRun

Плюсы

- распространённое название в CI/CD и тестировании;
- короткое.

Минусы

- звучит как запуск процесса;
- плохо описывает длительную игру.

---

### QuestSession

Плюсы

- хорошо отражает игровую сессию.

Минусы

- плохо сочетается с LevelSession;
- вызывает ассоциации с HTTP Session.

---

### QuestInstance

Плюсы

- корректно отражает экземпляр объекта.

Минусы

- слишком техническое название;
- не используется игроками.

---

### QuestParticipation

Плюсы

- отражает участие команды.

Минусы

- слишком длинное;
- неудобно использовать в коде.

---

### QuestProgress

Плюсы

- отражает процесс прохождения;
- естественно сочетается с LevelProgress;
- одинаковая терминология для всех runtime-сущностей.

Минусы

- описывает состояние, а не сам объект.

---

## Decision

Использовать термин **Progress**.

Будут существовать пары сущностей:
Quest → QuestProgress
Level → LevelProgress
Code → CodeSubmission
Hint → HintUsage

---

## Consequences

Преимущества:

- единый язык предметной области;
- легко понимать различие между описанием игры и её прохождением;
- одинаковый стиль именования всех runtime-сущностей.

Недостатки:

- потребуется немного больше сущностей в модели.
